# Site map

**In plain words:** the website has a single page. Everything else is behind-the-scenes "API" addresses that
the page (or Telegram) calls. All of them except the status check need the access key.

## Pages

| Path | What it shows |
|---|---|
| `/` | Portrait phone: the **avatar screen** (Jeannie full height, her words as subtitles, buttons to switch to the HUD, pick an outfit (wardrobe) and hold to talk; during the first Hangeul sync, a notice that asks first on mobile data, then shows progress). Elsewhere: the **HUD** (chat terminal, metrics, memory panel, Hangeul Sync panel, camera, smart-home grid); `1 \| 2` in the header switches between the classic HUD and Jeannie standing in the left frame (with its own wardrobe button). A choice made on a device is remembered there. Offline, both show a banner and disable the input. |
| `/manifest.webmanifest` | PWA manifest (generated by `src/app/manifest.ts`) |
| `/sw.js`, `/avatar/*`, `/icons/*` | Static files from `public/` |
| `/ort/*` | onnxruntime-web's WASM runtime for the device's question embedder, copied from `node_modules` by `scripts/copy-ort.mjs` before `dev` / `build` (git-ignored) |

The QA emote picker shows on every Vercel preview, and on a local build with `?debug=emotes`; never on production.

## API routes

"Key" means `JEANNIE_ACCESS_KEY`, sent as `x-jeannie-key: <key>` or `Authorization: Bearer <key>`
(`src/lib/auth.ts`). When the key is not configured, routes marked "key" are open, but nothing is *trusted*:
memory recall needs a proven secret. "Key **set and presented**" means the route refuses with 403 when
`JEANNIE_ACCESS_KEY` is not configured and 401 when it is not sent; the Hangeul routes also answer 503 when
Supabase is not configured (`src/lib/hangeul/http.ts`). `CRON_SECRET` never unlocks the Hangeul data.

| Route | Method | Runtime | Auth | Does | Calls |
|---|---|---|---|---|---|
| `/api/status` | GET | Edge | **open** | Booleans and model names: is a key required, which LLM, memory/search/voice/Telegram configured, `hangeul.configured`. `hangeul.records` and `hangeul.lastRuns` are filled only for a caller presenting the key | `env.ts`, `hangeul/store.ts` |
| `/api/chat` | POST | Edge | key (a Hangeul answer also needs the key set and presented; otherwise a fixed line says so) | Body `{messages[≤50], image?, lang?, hangeul?}` (image ≤3 MB data URL; `hangeul` is the device's `{embedding?, hits?}` for a Hangeul question). Streams the reply as text; headers carry agent, language, provider, honorific, sources | `agents/orchestrator.ts` |
| `/api/session` | GET | Edge | key | `?awayMs=` → the opening Korean greeting (model-written, template fallback in ~4 s) | `agents/greeting.ts` |
| `/api/search` | GET `?q=` / POST `{query, maxResults?}` | Edge | key | Live web search results | `agents/search-agent.ts` |
| `/api/tts` | POST `{text ≤2000, lang?}` | Node | key | MP3 of the text (ElevenLabs → Edge TTS); 503 tells the page to use browser speech | `agents/tts-engine.ts` |
| `/api/memory` | GET / POST / PATCH `?id=` / DELETE `?id=` | Node | key **required** (403 if no key is configured) | List, upload (`{name, content, pinned?}` or multipart, ≤1 MB `.md`/`.jsonl`), pin, delete notes | `memory/store.ts` |
| `/api/hangeul` | GET | Node | key **set and presented** | The Hangeul data's state for the HUD metrics: `{configured, records, lastRuns, latestBrief, latestReport}` (counts, keys and times; no student data) | `hangeul/store.ts` |
| `/api/hangeul/snapshot` | GET `?cursor=` | Node | key **set and presented** | One ~3 MB page of the full dump (records and chunks, vectors as base64 float32) for a device's first sync; follow `next` until null; `max_seq` is where `/changes` starts | `hangeul/store.ts` |
| `/api/hangeul/changes` | GET `?since=&limit=` (1–1000, default 200) | Node | key **set and presented** | The change log after the device's cursor, each upsert with its current record and chunks; call again with `next_seq` while `more` | `hangeul/store.ts` |
| `/api/hangeul/runs` | GET | Node | key **set and presented** | Hangeul BOT's recent finished runs (job, times, status, kinds read; no student data): what dates the "as of" line of an answer built on a device | `hangeul/store.ts` |
| `/api/hangeul/ask` | POST `{question, lang?, embedding?, hits?, prose?}` | Node | key **set and presented** | A server-side Hangeul answer as JSON (text, plan, facts, tables, as-of line). `prose: false` skips the model. The HUD itself asks through `/api/chat` | `hangeul/respond.ts` |
| `/api/telegram/webhook` | POST | Node | `x-telegram-bot-api-secret-token` must equal `TELEGRAM_WEBHOOK_SECRET` (refused if unset) | Handles Telegram updates; only the admin chat gets answers | `telegram.ts` |

Errors are JSON `{error, code}` with a 4xx/5xx status (`src/lib/utils.ts` `errorResponse`).
